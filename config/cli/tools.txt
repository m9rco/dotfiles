# 现代 CLI 工具清单。每行一个工具：
#
#   <逻辑名>|<平台>|<标签>|<回退安装方式>|<一句话说明>
#
# 逻辑名 -> 各平台包名的映射在 platform/*.sh 里，这里只出现逻辑名。
# 新增工具只需加一行，安装逻辑不用改。
#
# 平台：macos / linux / windows，空格分隔；all 表示三平台都装。
# 标签：essential = 默认安装，且装不上则模块失败
#       default   = 默认安装，装不上只告警（shell 配置会优雅降级）
#       optional  = 需显式选择
# 回退方式：包管理器里没有时依次尝试，形如 cargo:crate / npm:pkg /
#           script:URL / github:owner/repo。多个用空格分隔，单个 spec
#           内部不能有空格 —— 这一列是被 word-split 后传下去的。
#
#           github: 拉项目自己发布的预编译二进制。清单里只写来源仓库，
#           资产名与归档结构在 lib/release.sh 的配方表里：二进制从哪来
#           是读清单的人该一眼看到的，资产名不是。
#
#           留空有两种含义，看那一行上方的注释：
#           要么是「查过，这个项目没有官方预编译二进制」（tmux/htop），
#           要么是「仓库里到处都有，不需要」。不是「还没人想过」。
#
# 关于 essential 与 default 的界线：
# 所有工具在 zshrc.d 里都做了「存在才启用」，所以没有一个是缺了 shell 就坏。
# 区别在于装不上的损失：starship 是 prompt，缺了外观立刻退化，而且它是
# zsh 与 PowerShell 共用同一份配置的那个点 —— 跨 shell 一致性的核心。
# 其余工具缺了只是少个便利命令，不该让整台机器的引导以非零退出。
#
# 包源贫乏的发行版（RHEL/CentOS 7 最典型）上这个区分很实在：那里
# eza/lazygit/gh/yq 在任何仓库里都没有，若它们算致命，引导永远失败。

# ---------------------------------------------------------------- 搜索与浏览

ripgrep|all|default|cargo:ripgrep|grep 的替代：默认尊重 .gitignore，快一个量级
fd|all|default|cargo:fd-find|find 的替代：语法直观，默认跳过隐藏文件与 .gitignore
bat|all|default|cargo:bat|cat 的替代：语法高亮 + git diff 标记，也用作 man 的 pager
eza|all|default|cargo:eza|ls 的替代：图标、git 状态、树视图（需要 Nerd Font）
fzf|all|default|github:junegunn/fzf|模糊查找器：Ctrl-R 历史、Ctrl-T 文件、Alt-C 目录

# ---------------------------------------------------------------- 导航

zoxide|all|default|cargo:zoxide|按使用频率跳目录，取代手写 cd 路径

# ---------------------------------------------------------------- git

delta|all|default|cargo:git-delta|git diff 的分屏高亮渲染，见 config/git/gitconfig
lazygit|all|default|github:jesseduffield/lazygit|git 的终端 UI：暂存、变基、冲突解决都比命令行快
gh|all|default|github:cli/cli|GitHub CLI：PR、issue、release，也用于 gh auth 给 git 提供凭据

# ---------------------------------------------------------------- 数据处理

jq|all|default|github:jqlang/jq|JSON 处理的事实标准
yq|all|default|github:mikefarah/yq|jq 之于 JSON，yq 之于 YAML/TOML/XML

# ---------------------------------------------------------------- prompt

# starship 的回退顺序刻意是「官方脚本 → cargo」而不是只有 cargo：
# 官方 install.sh 拉的是预编译二进制，几秒就好；cargo 要现场编译，
# 在 CentOS 7 那种机器上是几分钟外加一个 600MB 的工具链。
# 它是 essential（缺了 prompt 立刻退化），所以更要给一条不依赖编译的路。
starship|all|essential|script:https://starship.rs/install.sh cargo:starship|跨 shell 的 prompt，zsh 与 PowerShell 共用 config/starship.toml

# ---------------------------------------------------------------- shell 环境
#
# 这两个是「配置里已经引用、却没人安装」的补齐项 —— 缺了它们不报错，
# 只是对应功能静默失效，属于比装不上更难发现的问题。
#
# direnv 走 github: 而不是它官方的 install.sh：那个脚本是
# #!/usr/bin/env bash 且用了 [[ ]]，而 script: 回退是往 `sh -s --` 里灌，
# dash 上直接语法错误；它还把安装目录读作环境变量 bin_path，不认 --bin-dir。
#
# tmux 的回退列刻意留空：这个项目从不发布预编译二进制（release 里只有源码
# tarball，而且要 libevent+ncurses 才编得起来），同时 apt/dnf/yum/pacman/apk
# 全都收录了它。空在这里是「查过，没有」，不是「没想过」。

direnv|macos linux|default|github:direnv/direnv|进目录自动加载 .envrc，30-tools.zsh 已挂好 hook
tmux|macos linux|default||终端复用；20-omz.zsh 的 tmux 插件按它是否存在决定加载

# ---------------------------------------------------------------- 可选
#
# 下面都是「顺手好用但不是每台机器都需要」的工具。默认不装的两个理由：
# 引导要快，且其中多数在 apt/dnf 仓库里没有、回退到 cargo 要现场编译。
#
# 启用方式（两者等价）：
#   DOT_CLI_OPTIONAL="btop dust" ./bootstrap.sh --only modern-cli
#   DOT_WANT_BTOP=1 ./bootstrap.sh --only modern-cli
#
# atuin 单独说明：它会接管 Ctrl-R 并把历史存进自己的 SQLite 库 —— 这是对
# shell 历史行为的实质改变（好处是跨机器同步与更强的检索），所以即便
# 你想装全套，也该是一次明确的选择。

atuin|all|optional|cargo:atuin|shell 历史的加强版：SQLite 存储、跨机同步、模糊检索

# 系统监控
#
# htop 的回退列同 tmux —— 官方只发源码（要 ncurses），而五个包管理器
# 全都有它。btop 与 duf 有官方预编译二进制，但它们是 optional、默认不装，
# 等真有人要再按 lib/release.sh 的配方表加两行即可（btop 只有 Linux 资产）。
htop|macos linux|optional||交互式进程监控，top 的可用版
btop|all|optional||htop 的现代版：CPU/内存/网络都有图形化面板
dust|all|optional|cargo:du-dust|du 的替代：树状展示各目录占用，一眼看出谁在吃盘
duf|all|optional||df 的替代：彩色表格，自动区分真实设备与虚拟挂载
procs|all|optional|cargo:procs|ps 的替代：彩色输出、支持树视图与按端口查进程

# 开发常用
tldr|all|optional|cargo:tealdeer|命令速查：man 太长时看几个真实示例
hyperfine|all|optional|cargo:hyperfine|命令基准测试：多次采样 + 统计，bin/dot-bench 可用它
xh|all|optional|cargo:xh|HTTP 客户端：httpie 的用法，Rust 的启动速度
sd|all|optional|cargo:sd|sed 的替代：正则与替换语法直观，不用背转义规则
